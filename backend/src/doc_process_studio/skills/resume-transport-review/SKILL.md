# Resume Transport Review

## 使用场景

当用户希望批量审核简历，并筛选出“具有 5 年以上交通行业相关开发或产品经验”的候选人时，使用该 skill。

该 skill 假定：

- 每位候选人对应一个独立文档。
- 文档格式可能不同，但你能够先读取到文档正文。
- 你的任务重点不是做复杂版式处理，而是基于已读取的文本内容做行业相关性和年限判断。

## 工作流程

1. 先确认简历输入范围：
   - 如果用户给了目录，就逐个定位候选人文档。
   - 如果用户直接给了若干文件，就逐个处理。
   - 一份文档默认对应一位候选人。
2. 先读取每份简历正文：
   - 优先使用能直接提取正文的方式读取，不要先对排版做无关处理。
   - 如果文件名能体现候选人姓名，记录下来；否则从正文中提取姓名。
3. 对每份简历做三类判断：
   - 是否存在交通行业相关经验。
   - 交通行业相关经验是否累计达到 5 年及以上。
   - 是否触发人工审核。
4. 输出统一审核报告：
   - 符合条件
   - 不符合条件
   - 需要人工审核
5. 如果用户没有指定输出文件格式，默认输出 Markdown 报告；如需落盘，可直接生成 `resume-transport-review-report.md`。

## 核心判定口径

- 目标人群：
  - 具有交通行业相关“开发经验”或“产品经验”的候选人。
  - “开发”包括但不限于前端、后端、全栈、客户端、测试开发、架构、实施开发、数据开发、算法开发。
  - “产品”包括但不限于产品经理、解决方案产品、业务产品、平台产品，只要职责明确对应交通行业业务。
- 通过标准：
  - 明确存在交通行业相关经历。
  - 可确认的交通行业相关经历累计满 5 年及以上。
  - 不存在足以阻断判断的重大信息缺失；若存在，则转人工审核，而不是直接判不符合。

详细判定规则、行业范围、年限计算与人工审核条件，请读取 [`references/review-rules.md`](references/review-rules.md)。

## 年限计算要求

- 优先按“可确认的交通行业相关时间段”累计。
- 若简历同时写了任职时间和项目时间，优先用更具体、可验证且不重复计算的时间段。
- 多个项目发生重叠时，不要简单相加；应按自然时间去重累计。
- 如果只能确认“做过交通项目”，但无法确认对应时长，不可直接计入已满足 5 年，只能视情况转人工审核。

## 输出要求

- 报告必须明确写出：
  - 哪些简历符合条件。
  - 哪些简历不符合条件。
  - 不符合条件的具体原因。
  - 哪些简历需要人工审核，以及触发原因。
- 每位候选人的结论必须带证据摘要，至少包括：
  - 候选人姓名或文档标识
  - 文档路径
  - 交通行业相关角色类型（开发 / 产品）
  - 可确认相关年限
  - 结论
  - 结论依据或问题说明

输出格式优先参考 [`references/report-template.md`](references/report-template.md)。

## 人工审核触发规则

以下情况默认转人工审核，不直接给出“明确符合”或“明确不符合”的硬结论：

- 客户信息缺失
- 项目时间模糊
- 多个项目重叠异常
- 交通行业属性不明确
- 职责描述过短

如果还出现“正文无法有效提取”“关键时间轴缺失”“候选人身份信息无法定位”等情况，也可以一并标记为人工审核，但要单独说明原因，不要混淆为用户给定的固定规则。

## 审核行为要求

- 不要把“智慧园区”“政务平台”“ERP”“电商”“金融”“教育”等非交通领域经历误判为交通行业经验。
- 若项目名称带有“物流”“运输”“车队”“调度”“公交”“客运”“货运”“轨道”“路网”“收费”“ETC”“信控”“车路协同”“出行”等关键词，应结合客户、业务对象、职责再判断，不要只看关键词。
- 只在证据充分时判定“符合条件”。
- 证据不足但存在较强可能性时，优先放入“人工审核”。
- 证据明确表明相关经验不足 5 年或根本不属于交通行业时，再判定为“不符合”。
