> 用途：作为事故报告生成的**写作范式基准（golden sample）**，定义"好报告"的颗粒度与证据标准。
> 建议放置：`backend/src/doc_process_studio/skills/incident-report/references/golden-samples/`

## 一、这份报告为什么是"好报告"（给模型看的核心标准）

### ✅ 它做到的四件事

1. **每个论断都指向具体实体**
   不写 "the storage system",而写 "**CHT Synology Data Storage NAS1 and NAS2**"。

2. **每个论断都带时间戳**
   不写 "recently",而写 "**shutdown automatically at 20:35, 12 Mar 2026**"。

3. **业务影响可验证**
   不写 "service was impacted",而写
   "**Partial CHT transactions stopped uploading from 17:07 to 22:50**"。

4. **结论有数据表格支撑**（最关键，现有生成完全缺失）
   用 `Toll Point | Time Range | No. of Transactions` 表格给出 40,418 笔受影响交易。

### ❌ 现有生成常见的坏写法（对照）

| 坏写法 | 为什么坏 | 应改成 |
|---|---|---|
| "The system was significantly impacted." | 不可验证、无实体、无时间 | 指明哪个设备/组件、什么时段、什么业务行为 |
| "Service performance degraded." | "degraded" 无量化 | 给具体指标或具体业务后果 |
| "Root cause was hardware issue." | 过于笼统、无因果链 | 展开因果链（见下） |
| "Will follow up with vendor." | 不可执行 | 给出厂商建议的具体版本/动作 |

## 三、正文段落（写作范式，逐段拆解）

### 标题与描述

```
Incident Report of DAS CHT Performance Degradation

Description of the Incident:
DAS CHT Performance Degradation Accidentally on 12 Mar 2026
Affected Date: 12 Mar 17:04 – 13 Mar 11:30
```

**要点**：标题 = `Incident Report of <系统> <现象>`；Affected Date 用区间，精确到分钟。

---

### Impact（⭐ 本报告的精华）

```
Both CHT Synology Data Storage NAS1 and NAS2 status were unstable.
NAS2 status was abnormal and shutdown automatically at 20:35, 12 Mar 2026.
NAS1 is now active as standalone.

Partial CHT transactions stopped uploading from 17:07 to 22:50, 12 Mar 2026.

Most of services includes time service was impacted due to Synology Data Storage abnormal.
```

**结构拆解**：
1. **设备状态层**：哪个设备、什么状态、什么时候发生、当前状态（NAS1 standalone）
2. **业务后果层**：什么业务行为、什么时段、停了多久（transactions stopped uploading 17:07–22:50）
3. **服务波及层**：哪些服务受影响（time service）

**然后紧跟数据佐证表格**：

```
Missing Backlog Transaction Re-generated as below

| Toll Point    | Time Range                  | No. of Transactions |
|---------------|-----------------------------|---------------------|
| CHT3 (Active) | 18:11 – 18:59 12/03/2025    | 2,330               |
| CHT4          | 18:02 – 19:07 12/03/2025    | 2,909               |

No Tag Record or Time Sync issue affected Tag Mapping record count and period as below.

| Toll Point | Time Range                          | No. of Transactions |
|------------|-------------------------------------|---------------------|
| CHT1       | 17:14, 12/03/2026 - 17:46, 12/03    | 1,448               |
| CHT1       | 06:55, 13/03/2026 - 11:32, 13/03    | 13,088              |
| CHT3       | 17:07, 12/03/2026 - 22:15, 12/03    | 13,328              |
| CHT3       | 07:01, 13/03/2026 - 11:30, 13/03    | 12,554              |

```

⭐ **这是现有生成系统与真实报告最大的差距**：真实报告的 Impact 以**量化表格**收尾，
现有系统只输出散文。

### Root Cause（因果链写法）

```
Extreme I/O load stalled NFS/filesystem, triggering HA failover loops.
Replication couldn't complete, causing data inconsistency.
HA detected data inconsistent on Node 2, marked volume crashed, then auto-shutdown.
```

**结构拆解**：三段递进的完整因果链
```
I/O 负载异常
  → NFS/文件系统停滞
    → HA 反复 failover
      → 复制无法完成
        → 数据不一致
          → HA 判定 Node 2 volume crashed
            → 自动关机
```

**要点**：每一环都是**技术动作**，不是"hardware issue"这种黑箱。

---

### Follow-Up Actions（可执行性）

```
Synology advised upgrading NAS1 and NAS2 DSM version to 7.3.2 to improve
storage stability and performance.

Supplement a detailed "Synology HA Remediation and Storage Rebuild Plan for
CHT Incident on 12 Mar 2026" as attached.

Coming up recovery action including:
- Move all running servers VM to MSA (Temporary Storage)
- Update the firmware of Synology
- Rebuild new HA cluster
- Move all running servers VM back to Synology HA Cluster
```

**结构拆解**：
1. **厂商建议**（带具体版本号 7.3.2）
2. **附件引用**（详细整改方案）
3. **有序步骤列表**（4 步，每步都是可执行动作）

## 四、可复用的写作规则（提炼给 prompt 用）

```yaml
impact:
  - 必须点名具体设备/组件（含型号或编号）
  - 必须给出故障发生与恢复的精确时间戳
  - 必须说明受影响的业务行为（不是"系统受影响"，而是"什么业务动作停了"）
  - 凡提到数量/时段，尽量附数据表格；无数据则写 N/A，不要含糊
  - 禁止: "significantly impacted" / "severe impact" / "affected to some extent"

root_cause:
  - 写成因果链，每环是一个技术动作
  - 终点应是可观测的现象（auto-shutdown / failover loop / data inconsistent）
  - 禁止: "hardware issue" / "system error" / "unknown reason"

follow_up:
  - 有厂商建议则写明具体版本或补丁号
  - 整改动作必须有序且可执行（动词开头）
  - 禁止: "will follow up" / "monitor the situation"

format:
  - Affected Date 用 "12 Mar 17:04 – 13 Mar 11:30" 区间格式
  - 时间统一 DD/MM/YYYY HH:MM
  - 全英文输出
  - 缺失值写 N/A，不编造
```

## 五、已知术语（本项目域）

| 术语 | 含义 |
|---|---|
| CHT | 收费站点（本例：Cheung Sha Wan / 青衣等隧道类站点的收费点标识） |
| DAS2 | 文档/系统编号体系（Fault Log Form 前缀） |

| Synology Data Storage | 存储子系统，本报告故障归属系统 |
| Toll Point | 收费点（CHT1 / CHT3 / CHT4 等） |
| Tag Mapping | 标签/交易映射记录 |
| Time Sync / time service | 时间同步服务（本例受影响） |
| MSA | 临时存储（迁移目标） |
| DSM | Synology 操作系统（本例建议升级到 7.3.2） |
| SOC | 报告人（安全运营中心） |
